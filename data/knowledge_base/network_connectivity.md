# 网络连通性故障排查

## 分层排查思路

网络连通性问题应按 OSI 模型自下而上排查：

1. 物理层：网线、光模块、接口指示灯。
2. 数据链路层：VLAN 划分、MAC 地址表、STP 状态。
3. 网络层：IP 配置、路由表、默认网关。
4. 传输层：端口可达性、防火墙策略。
5. 应用层：DNS、代理、应用服务状态。

## 典型场景

### 能 Ping 通网关但无法上网

可能原因按可能性排序：

1. DNS 解析故障（最常见）。
2. 默认路由缺失或错误。
3. 出口 NAT 配置异常。
4. 上联链路或运营商故障。
5. 本机代理设置错误。

排查建议：

- 先用 IP 直连测试（如 `ping 223.5.5.5`）区分 DNS 问题与路由问题。
- 检查 `route print` 或 `ip route` 确认默认路由存在。
- 查看出口设备 NAT 转换表是否正常。

### 完全无法 Ping 通网关

可能原因：

1. 网线未连接或接口 down。
2. 本机 IP 配置错误（IP/掩码/网关）。
3. VLAN 划分错误，未进入正确广播域。
4. 交换机接口被关闭或划入错误 VLAN。
5. ARP 表异常。

## 接口状态判断

- `up/up`：接口物理与协议均正常。
- `up/down`：物理正常但协议异常，常见于对端未配置或封装不匹配。
- `down/down`：物理链路断开，检查线缆与对端接口。
- `admin down`：接口被人为关闭，需确认变更记录。
